# git 工作流约束

本技能仓库采用功能分支策略，保障历史可追溯、可回滚。

## 规则

1. **启动前拉取**：开工前 `git fetch`；有远端更新先 `git pull --ff-only`。
   本仓为**本地仓（无远端）**，无远端时该步记为「不适用」，不得伪造。
2. **功能分支提交**：每个步骤完成后在 `feature/<topic>` 提交，分支名不得为 `main`/`dev`。
3. **审核通过后合并到 dev**：双链辩论通过且悬空链接为 0 后，合入 `dev`。
4. **整体审核通过后合入 main**：九项审查标准全部通过后 `dev` → `main`。
5. **禁止直写 main/dev**：所有变更须经功能分支进入。
6. **重试熔断**：审查失败重试达 10 次触发惩罚，回退分支或求助用户。
7. **忽略清单**：`.gitignore` 必含 `tmp/` 与 IDE 目录；暂存前核对 `git status`。
8. **自动 git init**：目录无 `.git` 即先 `git init`，不得跳过。
9. **推送前确认**：本仓按用户指令**不推送远端**；将来加远端须用户当轮确认，
   并先判定可见性（第 10 条）。
10. **仓库可见性**：含用户保密内容或疑似违规可能者须 PRIVATE；判定不了须询问用户。
11. **附属技能双仓模型**：附属／私有子技能进独立私有伴生仓（`private/` 工作树），
    本体仓 ignore `private/` 仅留 `.gitkeep`；禁止不入库或误推公开仓。

## 违规后果

跳过功能分支 → 无法按步回滚；跳过审核 → 缺陷直接进主分支；
漏配 ignore → 临时工件入库；未确认即推送 → 未经同意发布。
