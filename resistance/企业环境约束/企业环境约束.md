# 企业环境约束（红线）

企业／域环境的策略与拦截是 Windows 应用事故的高发区，**一律以实测为准**。

## 必须

1. 组策略影响（软件限制、AppLocker、Windows Defender Application Control、
   启动脚本、WSUS 更新策略）须来自目标域机的实测或策略导出，不得凭默认模板推断。
2. 杀软／EDR 白名单：新增可执行、服务、计划任务、命名管道监听前，
   须确认是否需报备与加白；结论须给「已加白／未加白／待确认」三态之一。
3. 域机上的 UAC 与本地管理员策略可能禁止提权：`runas` 路径须实测，
   不得以开发机行为外推。
4. 证书链可能由企业私有根 CA 签发：校验须包含链构建（`sign_probe`），
   不接受「自签即可」的建议。
5. 更新通道受控（WSUS／Intune）时，自动更新方案须与管控通道一致。

## 禁止

- 禁止建议关闭 Defender／ASR／SmartScreen 作为「解决方案」而不留回滚与审批记录。
- 禁止把「域策略拒绝」误判为「代码缺陷」，或反之——须分别取证。
- 禁止在无实测的情况下断言「企业环境不受影响」。

## 兜底

无法接触域机时：输出「域机取证清单」（命令＋期望值＋判读规则），标注 `[待实测]`。

## 违规后果

发布后在客户域机上无法安装／启动，回滚成本高且影响用户系统安全姿态。
