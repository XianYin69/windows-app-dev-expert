# 审查约束（整体审查得出的项目级约束）

整体审查＝九项标准逐项过，任一不过即记中断并回到对应步骤修复。

## 九项标准

1. **结构完整**：`SKILL.md`、`agent/` 四格式、`asset/`、`references/`、`dependence/`、
   `resistance/`、`branch/`、`planned_tasks/`、`scripts/`、`LICENSE`、`CHANGELOG.md` 齐备。
2. **链接闭合**：悬空链接为 0（`python -B scripts/check_links.py --root .`）。
3. **长度红线**：所有 `.md` ≤ 50 行（脚本文件不限行数，但禁裸 except、调试残留、
   > 100 字符长行、超长函数）。
4. **依赖合规**：`deps.json` 每条含 `name/source_url/license/version/install/checked_at`，
   `source_url` 为原始链接（`python -B scripts/knowledge_index.py --check-deps`）。
5. **脚本可执行**：`scripts/` 内每个探针可独立运行且相对技能根真实存在（含扩展名）。
6. **知识树闭合**：九叶的 `knowledge/` 与 `checklists/` 文件一一对应，
   且 `knowledge_tree.json` 路径全部可达。
7. **约束齐备**：`resistance/` 含 git 工作流、平台假设、企业环境、注册表与服务安全、
   浏览器学习、薄技能依赖、约束部分、降级策略、沙盒、五大机制。
8. **计划任务合规**：字段名与 SMS 读取端一致，一任务一文件，技能自身无执行入口。
9. **版本与许可**：YAML frontmatter 完整（name/version/description/license/metadata），
   `CHANGELOG.md` 记本次变更，`LICENSE` 为 MIT。

## 辩论要求

审查节点须跑正反双链辩论（`logic_chain.py debate`），pro/con 论据清单落链后再裁决。

## 失败处理

记 `process_chain interrupt` → 修复 → `resume`；重试达 10 次触发惩罚熔断。
