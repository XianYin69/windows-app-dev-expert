# 修改流程

## 适用

对本技能已有内容（细则、清单、脚本、约束、依赖）的增删改，独立于顾问路径。

## 动作

1. **定位**：明确改哪个文件、哪一节，属哪个叶或哪个机制目录。
2. **镜像**：变更一律先写 `tmp/` 镜像，禁止就地改本体（见
   [update 接口](../../../update/update.md)）。
3. **一致性**：改叶内容须同步 `asset/knowledge_tree.json`、
   `references/知识树/知识树.md` 与 `SKILL.md` 知识树段；改依赖须同步 `deps.json`。
4. **约束**：`resistance/` 内约束不得删除；修改约束须记 `CHANGELOG.md` 与违规后果。
5. **审查**：跑九项标准（见 [审查约束](../../../resistance/审查约束/审查约束.md)）
   ＋ 正反双链辩论。
6. **释放与提交**：compare → release → 功能分支提交 → `dev` → `main`（本地）。

## 产出

- 差异摘要（新增／修改／删除文件清单）＋ 自检结果。
- 过程链：`完成项目修改`。

## 兜底

- 冲突（本体已被外部改动）→ 停 release，报告冲突项等用户裁决。
- 越界（目标不在本技能目录）→ 拒绝执行，改由调用方统一挂接。
