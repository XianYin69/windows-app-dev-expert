# 问题解析

## 动作

1. 复述问题为可判定命题：把「界面卡顿」改写为「UI 线程在 X 场景阻塞 Y ms」。
2. 定范围：是否属本技能（Windows 桌面／系统应用）；
   Qt／QML → 转 `qt-qtquick-expert`；Web 前端与视觉 → 转 `interface-design-expert`。
3. 定形态：打包（MSIX／包标识）或非打包桌面；服务／托盘／安装器／命令行工具。
4. 定口径：目标 Windows 版本、运行时（.NET TFM／MSVC／Rust）、shell（5.1／7）。
5. 缺关键信息（目标机、是否域、是否可提权）时向用户提问，一次一问。

## 产出

- 命题一句话 ＋ 范围判定（本技能／转派）＋ 待取证清单。
- 逻辑链：范围与形态判定的 `frm → to : why`。

## 兜底

- 范围模糊 → 按「先取证后判断」列两种形态的判据差异，不擅自选边。
- 用户不响应关键问题 → 按最保守假设（非打包、只读取证）继续并标注假设。
